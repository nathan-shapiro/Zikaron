# M14 — The harness seam, both clients, and the gist character bound — review

## Round 1 — 2026-08-16

**Summary judgment.** This is a strong milestone: the seam genuinely carries harness differences as data (I found no harness branch hiding downstream of it — `tripwire`'s scoping travels as a spec field, `subagent_policy` resolves through `detect` rather than assuming its caller, `limits.MAX_OUTPUT_SIZE` derives from the table), the drift guard against `design/harness.md` fails closed at every extraction step, the character bound is enforced at the single write-path entry (`writes.prepare` → `plan_chunks`) so all three writers are covered, and the new comments are clean against coding-standards §5. Two things keep it from shipping as-is: the milestone's central cross-client property — the hook sending the seam-resolved label — is not actually pinned by any test (a hook that sent the wrong label would pass the whole suite), and the CHARACTERS budget unit rests on an unmeasured code-points-vs-UTF-16-units assumption that the probe's own unit-pinning experiment could not distinguish.

### Findings

1. **[BLOCKER] No test pins that `push.run` sends the seam-resolved label in its envelope — the done-when's "both clients resolve an identical label under each harness's own variable" is demonstrated for only one client.** `tests/test_harness_detect.py::TestBothClientsResolveTheSameLabel` asserts the MCP client adopts exactly what the seam resolves, under both harnesses, including the bootstrap fall-through — good. The hook side has no counterpart: `tests/test_hook_rpc.py` tests `surface_once` against a *given* envelope, `tests/test_hook_envelope.py` tests `build_envelope` against given arguments, and every `push.run` test's fake service (`_FakeSurfaceService._answer`) discards the request's `client` object unread. So an implementation of `push.run` that passed `payload_session_id` — or a constant — into `build_envelope` instead of `env_session_id` (one argument at `zikaron/hook/push.py:94`) passes the entire suite; the suppression tests cannot catch it because on every non-suppressed path the two values are either equal or the payload's is what a broken build would send. The fake service already parses each request, so the fix is small: retain parsed requests on `_FakeSurfaceService` (e.g. `self.requests: list[dict]`), and in a happy-path test under **each** harness (for Claude Code: set `CLAUDECODE=1` and `CLAUDE_CODE_SESSION_ID`, payload matching) assert `request["params"]["client"]["session_id"]` equals the environment variable's value; add one more asserting it is `None` when no variable is set. That also closes the currently-untested "hook proceeds to surface under Claude Code" path — today only the divergence half of the CC hook behaviour is exercised.

2. **[IMPROVEMENT] `BudgetUnit.CHARACTERS` silently assumes Claude Code counts Unicode code points, and the probe that pinned the unit cannot support that.** `HarnessSpec.exceeds_injection_budget` (`zikaron/harness/spec.py:96`) measures `len(text)` — Python code points. The unit-pinning measurement (`harness.md` §"Injection budgets": 9,016 × `漢` arrived whole) distinguishes characters from *bytes*, but `漢` is a BMP character — one code point **and** one UTF-16 code unit — so it cannot distinguish code points from UTF-16 code units, and Claude Code is a Node application whose string lengths are naturally UTF-16 units. If the harness counts units, every astral character (emoji included, which real gists do contain) counts 2 there and 1 here, and the "worst-case five-row block fits 10,000" claim fails in that corner: 6,087 code points of astral-heavy gists is up to ~11,200 units. The failure is loud under Claude Code (notice + preview + path), so the consequence is bounded — but this document's own rule is that unmeasured claims get marked. Suggested, in ascending cost: (a) mark the assumption in `BudgetUnit.CHARACTERS`'s docstring and in `harness.md`'s Injection-budget row (*"characters" = code points, assumed; not distinguished from UTF-16 units by the probe*); (b) name the decisive probe for M16 — rerun the bisection with a 4-byte astral character, which separates all three candidate units at once; (c) if provability is wanted now, measure character budgets as `len(text.encode("utf-16-le")) // 2`, which upper-bounds both interpretations and costs nothing on this path.

3. **[IMPROVEMENT] `detect._MINTED_PREFIX` is an unguarded copy of `zikaron/service/envelope.py::_MINTED_PREFIX`.** Every other cross-boundary copy this codebase keeps is drift-guarded by a test that pays the import cost — `envelope.CLIENT_KIND` against `ClientKind.HOOK.value`, the `HookEnvelope` fields against `ClientEnvelope`, `subagent_policy.CONSOLIDATOR_AGENT_TYPE` against `install.entries` (that last one built in this very milestone). One test in `test_harness_detect.py`: `from zikaron.service import envelope as service_envelope; assert detect._MINTED_PREFIX == service_envelope._MINTED_PREFIX`.

4. **[IMPROVEMENT] `hook/main.py`'s module docstring justifies payload dispatch with a harness fact that appears false.** Lines 5–8: "Neither supported harness offers a per-trigger argument-injection mechanism, so the payload is the only place the trigger name is actually available to branch on." Both harnesses accept an arbitrary command string per trigger entry — kiro's object format keys entries by trigger with a `command` each, and Claude Code's `settings.json` hooks are per-event arrays of commands — so `zikaron-hook --event spawn` is trivially expressible in either; nothing in `harness.md` states this fact, and M14's whole discipline is that harness facts are sourced. The actual reason is better and true: one identical command registered under every trigger keeps the installed entries uniform, and the payload's own `hook_event_name` cannot disagree with the event that fired it the way an argv flag copied into N config entries can. Replace the false sentence with that.

5. **[IMPROVEMENT] An empty-string session variable is treated as a *present* label by the seam and as *null* by the service — and under kiro the disagreement silently kills push.** `detect.session_label` (`zikaron/harness/detect.py:79-82`) forwards `""` (it is neither absent nor `zk-`-prefixed), on the stated ground that the value is "the service's to validate" — but the service's own `_conforms` (`zikaron/service/envelope.py:84`, `0 < len(...)`) treats `""` exactly like null and mints. Meanwhile the *client-side* consumer of the same value does act on it: `is_subagent_session(env_session_id="", payload_session_id=<real id>)` returns `True`, so `KIRO_SESSION_ID=""` (an exported-but-empty variable, e.g. from a wrapper script) suppresses every top-level push with no log line at all, and under Claude Code produces a tripwire line per turn. Since the marker already takes the conservative reading of emptiness, the session variable should match the service's own definition of "a label": return `None` when the value is empty. One line in `session_label`, one test beside `test_returns_none_when_absent`.

6. **[NITPICK] `zikaron/core/indexing/writes.py:158-162` — `prepare`'s Raises docstring was not updated for the new bound.** It still reads "`BOUNDS` if the gist or content is empty or the gist is over `gist_max_tokens`", omitting the character bound the same call now enforces first. Add the clause (and the `gist.characters` field name, since that is the part of the contract a caller acts on).

7. **[NITPICK] `tests/test_install_limits.py:166-171` hard-codes `internal_deadline_seconds = 2.0` instead of importing `push._DEADLINE_SECONDS`.** If the real deadline moves, this test keeps asserting the ×2 margin about a number the hook no longer uses. Import the constant so the margin claim tracks the code it is about.

**Checked and clean, for the record:** no harness identity test exists anywhere downstream of the seam (the one `spec is KIRO` comparison is in the drift test's own column selection, which is legitimate); the stdlib-only guard discovers `zikaron/harness/*.py` from disk and its self-tests prove the discovery is live; the tripwire's scoping travels as `fires_hooks_for_subagent_sessions` rather than a harness name, is asserted to write nothing under kiro and exactly one closed-vocabulary line under Claude Code, and never raises on hostile directories; the suppression path makes no RPC (proven by the absence of any bound service in those tests); `SubagentStart` is policy-only on the `additionalContext` channel with byte-exact stdout assertions for the other two events and genuinely-empty output for the consolidator; `SubagentStop` is asserted out of the vocabulary, keeping the hook write-path-free; the character bound is checked before the token bound with the unit in the field name, drift-guarded against `schema.md` §Bounds, and the worst-case block assertions use the real `render` framing rather than the quoted 967; the kiro ×4 byte ceiling is exercised with a genuine 4-byte character; `check.sh` covers `zikaron/harness`; the scope fence held (no installer changes, both kiro hook formats intact); and the conftest environment scrub correctly declines to be the misdetected inner session.

### Findings

Update the `chunking.py` docstring arithmetic, `design/harness.md` §"Injection budgets" ¶3, and the unit note behind `gist.characters`. The cheaper alternative, if the write-path change is unwanted this late: keep code points, add an astral variant of the worst-case test asserting the overrun *as a recorded fact*, scope the existing test's name to what its fixture proves, and state the corner in `harness.md` beside the loud-overrun paragraph.

2. **[IMPROVEMENT] `detect.current_harness`'s docstring still asserts the behaviour and rationale this round's own fix refuted.** `zikaron/harness/detect.py:43-47`: "while a session variable's value is forwarded whatever it is (`session_label`). 3. **[NITPICK] `remember`'s Raises docstring was not updated alongside `prepare`'s.** `zikaron/core/indexing/writes.py:421-422` still enumerates "`BOUNDS` if the gist or content is empty or the gist exceeds `gist_max_tokens`", omitting the character bound `prepare` (which it calls) now documents first — and `amend`:443 defers to `remember`, inheriting the omission.
